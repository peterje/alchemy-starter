# Agent guide

This repository is a template. Every file is an example future code will copy, so keep changes idiomatic and delete anything that is not pulling its weight.

## Architecture

- `apps/website/src/notes.ts` is the contract: schemas, branded IDs, typed errors, and the `HttpApi` definition. The browser imports it, so it must never import `alchemy`, `cloudflare:workers`, or `worker.ts`. The Vite build fails if it does.
- `apps/website/src/worker.ts` is the only server implementation. It defines the Alchemy Worker, the per-user Durable Object, its SQL migrations, and the `HttpApi` handlers.
- `apps/website/src/routes/` holds TanStack Start file routes. `routeTree.gen.ts` is generated by the Vite plugin. Never edit it.
- `alchemy.run.ts` wires the Worker and website together. Infrastructure is Effect code, not YAML.

## Adding things

- New endpoint: add it to `NotesApiGroup` in `notes.ts`, implement it in the Durable Object handlers in `worker.ts`, and call it from the UI with `client.query` or `client.mutation`. The Worker forwards every `/api/users/:userId/*` request, so it needs no change.
- New schema change: append a SQL string to `migrations` in `worker.ts`. Never edit or remove a shipped migration.
- New page: add a file under `routes/`. The route tree regenerates on the next build or dev run.

## Rules

- Application state lives in Effect Atom. Do not use React `useState`, `useReducer`, or `useEffect`.
- Data access goes through the shared `HttpApi` contract. Do not add TanStack server functions.
- Parse input at the I/O boundary with Schema. Do not accept `unknown` or `object` parameters or narrow with `typeof`.
- Every type assertion needs a `SAFETY:` comment stating the checked invariant. Prefer fixing the type.
- Put imports at the top of the module. In a `switch` over a union, add a `never` check in `default`.
- Comments explain why, not what. Keep them for I/O, validation, and edge cases.

## Commands

```bash
bun run check               # formatting, lint, types, lint-rule tests, build
bun run test:integration    # deploy to local workerd and test the HTTP API
bun run test:browser        # Playwright against a separate local stage
```
